# Threat model

This V1 assumes the local user and their repositories can contain hostile paths, staged data, and declarative configuration. It does not attempt to defend against a compromised user account or an attacker who can write the user's private runtime/cache directories.

| Threat | Mitigation and boundary |
| --- | --- |
| Command injection from BUFFER or aliases | The parser is data-only and rejects shell operators, substitutions, and unsupported grammar. The plugin contains no `eval`, never overrides `git`, and invokes the helper with quoted positional arguments. Git aliases and shell functions are not discovered or executed. |
| Generated-text injection | Candidates are deterministic, bounded, never executed, and restricted to a conservative character set. The parser emits quote closures or escaping as syntax data; acceptance is the user's normal autosuggestions action. |
| Local model / prompt injection | Ollama is loopback-only and receives bounded staged-only context marked as untrusted data. Repository text cannot alter the provider system constraint, schema, or evidence format. Non-streaming schema output is strictly parsed, bounded, structurally validated, and revalidated as a shell-safe candidate. Malformed output is discarded or follows the explicit deterministic fallback policy. |
| Unconsented cloud disclosure | OpenAI is default-deny behind a user-private `0600` provider-specific grant record, never repository configuration. Every request requires an exact current grant and staged-state proof; preview reports categories/bounds only. The compiler redacts and relevance-filters staged-only sources before the selected class subset reaches the transport. A missing key/grant or invalid private record sends nothing. |
| Cloud credential or cached-result exposure | The fixed OpenAI adapter reads `OPENAI_API_KEY` only after authorization, at request time. It has no credential/endpoint config fields and records only provider/model metadata plus a hash of the selected redacted context policy. Grant replacement/revocation removes provider-derived records, and every lookup reloads the grant before rendering. `store: false` is requested; it is not a guarantee of all provider-side data handling. |
| Unsupported model claims | Deterministic grounding verifies evidence IDs, basic commit shape, context-derived scopes, staged path/test evidence, and bounded branch issue IDs before ranking. Subject-component overlap and behavioral/fix evidence are marked heuristic; the product does not claim semantic proof. Unsupported candidates are rejected or demoted by a user-global ambiguity policy. |
| Malicious filenames or staged source | Context reads only fixed, capped Git index/history sources, uses literal pathspecs, excludes generated/vendor/lockfile content, redacts common secret forms, and never reads working-tree source. It treats source and path text as untrusted data and does not execute repository content. Redaction is defense in depth, not a claim that arbitrary secrets can be detected. |
| Malicious repository configuration | `.zsh-git-inlay.toml` is a strict allowlist of message-policy keys. It cannot select providers/endpoints, use credentials, enable activity/output capture, change permissions, run hooks, or execute code. Unknown keys fail validation. |
| Repository policy privilege escalation | Policy parsing accepts only conventional-message shape fields with bounded strings, arrays, and relative path-to-scope mappings. Built-in shell/message safety and user privacy/provider settings take precedence; malformed policy causes an unsupported state. |
| Stale-result races | Fingerprints cover repository, worktree, HEAD/unborn ref, branch, exact index tree, context/compiler and generator versions, and configuration. The strategy verifies its current fingerprint before lookup. A worker rechecks before and after publication; superseded jobs are cancelled, mismatched results are discarded, and the residual storage race is bounded by cache retention. |
| Cross-repository or linked-worktree leakage | The common Git directory and worktree Git directory are separately hashed in every fingerprint. Cache records carry both scope IDs and lookup checks them before returning a record. |
| Learning-profile leakage or poisoning | Learning profiles are private `0600` versioned aggregate files keyed by the hashed common Git directory, capped to 128 profiles/16 KiB each. They contain no raw commit text, source, activity, remote, credential, provider grant, or cache data. Policy and grounding filter candidates before bounded reranking. Only actual HEAD-changing commits update a profile; candidate display/cycling does not. Explicit clone transfer compares credential/query/fragment-stripped origin hashes and requires `--confirm`. The edited-candidate classifier is deliberately weak and documented as an inference. |
| Local socket access | The socket lives in a `0700` per-user directory and is `0600`; a live socket is not unlinked. Protocol version, framing, request/reply sizes, and fields are validated. [Inference] Private directory ownership and modes reduce other-user access on supported Unix systems; a compromised account is out of scope. |
| Unsafe temporary files or symlink replacement | Runtime/cache paths must be private directories and reject a symlink final path. Cache publication uses a private temporary file plus atomic rename. Exact fingerprints use a secure private directory and `0600` alternate index copy, so Git's cache-tree write never touches the real index. A non-socket at the socket path is refused. Parent XDG directories remain an operating-system/XDG trust assumption. |
| Compose editor injection or message-file substitution | `compose` accepts `GIT_EDITOR`, user-global `core.editor`, `VISUAL`, `EDITOR`, or `vi`; it deliberately ignores repository-local `core.editor`. It accepts only a resolved non-shell executable and literal unquoted arguments; it does not use `eval` or a shell. It writes a `0600` temporary file, and after editing uses `lstat` plus same-file verification to require a private regular non-symlink file within a 16 KiB limit. Unsupported complex editor settings fail closed; a user may configure a simple wrapper explicitly. |
| Stale compose body | Compose begins with an already prepared candidate that passes composition grounding eligibility for the exact fingerprint and re-snapshots after the editor returns. Any changed index, HEAD, branch, relevant configuration, or policy produces an error and retains the private edited file path; no stale text is reported as verified. It never invokes `git add` or `git commit`. Generated body facts are limited to staged status/path evidence. User prose is preserved as user-authored, not asserted to be generated evidence. |
| Oversized diff, request, or response | Exact index copies are capped at 64 MiB. Context command output is streamed into capped buffers; source budgets are 4/12/6/6/2/2/2 KiB plus 256/128 bytes for paths/patch/symbols/manifests/subjects/path history/convention/branch/issue, with 12 KiB aggregate for Ollama and 32 KiB deterministic preview. Candidate count is three, messages 160 bytes, buffers 4096 bytes, IPC requests 16 KiB, IPC replies/cache records 64 KiB, and persistent candidate storage has validated record/byte/age limits. |
| Rapid index-change denial of service | Active repository and generation-concurrency limits bound work; jobs for a superseded scope are cancelled. A large index is rejected at the configured safety limit. Rapid changes can still cause repeated snapshots and unreferenced Git tree objects, so this is mitigated rather than eliminated. |
| Release artifact substitution or accidental overwrite | The local snapshot target requires a new output directory, embeds an explicit version and commit, uses reproducible Go flags, and emits SHA-256 checksums plus a deterministic SPDX SBOM. Install prepares private temporary copies before replacing only the two named product files. No remote installer, publisher, package registry, release creation, or model download is invoked. A missing project license blocks redistribution rather than being inferred. |

There is no telemetry, automatic staging, automatic commit, hook execution, or
use of repository-supplied executable code. Ollama is an optional loopback-only
local provider; OpenAI is an optional explicit-grant cloud provider; no model
is pulled automatically. The plugin's ZLE path never calculates a diff,
compiles context, contacts a network, or runs generation; the daemon owns
bounded context collection and generation.
