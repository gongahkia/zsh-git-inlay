# Threat model

This prototype assumes the local user and their repositories can contain hostile paths, staged data, and declarative configuration. It does not attempt to defend against a compromised user account or an attacker who can write the user's private runtime/cache directories.

| Threat | Mitigation and boundary |
| --- | --- |
| Command injection from BUFFER or aliases | The parser is data-only and rejects shell operators, substitutions, and unsupported grammar. The plugin contains no `eval`, never overrides `git`, and invokes the helper with quoted positional arguments. Git aliases and shell functions are not discovered or executed. |
| Generated-text injection | Candidates are deterministic, bounded, never executed, and restricted to a conservative character set. The parser emits quote closures or escaping as syntax data; acceptance is the user's normal autosuggestions action. |
| Local model / prompt injection | Ollama is loopback-only and receives bounded staged-only context marked as untrusted data. Repository text cannot alter the provider system constraint, schema, or evidence format. Non-streaming schema output is strictly parsed, bounded, structurally validated, and revalidated as a shell-safe candidate. Malformed output is discarded or follows the explicit deterministic fallback policy. |
| Malicious filenames or staged source | Context reads only fixed, capped Git index/history sources, uses literal pathspecs, excludes generated/vendor/lockfile content, redacts common secret forms, and never reads working-tree source. It treats source and path text as untrusted data and does not execute repository content. Redaction is defense in depth, not a claim that arbitrary secrets can be detected. |
| Malicious repository configuration | `.zsh-git-inlay.toml` is a strict allowlist of future message-policy keys. It cannot select providers/endpoints, use credentials, enable activity/output capture, change permissions, run hooks, or execute code. Unknown keys fail validation. |
| Stale-result races | Fingerprints cover repository, worktree, HEAD/unborn ref, branch, exact index tree, context/compiler and generator versions, and configuration. The strategy verifies its current fingerprint before lookup. A worker rechecks before and after publication; superseded jobs are cancelled, mismatched results are discarded, and the residual storage race is bounded by cache retention. |
| Cross-repository or linked-worktree leakage | The common Git directory and worktree Git directory are separately hashed in every fingerprint. Cache records carry both scope IDs and lookup checks them before returning a record. |
| Local socket access | The socket lives in a `0700` per-user directory and is `0600`; a live socket is not unlinked. Protocol version, framing, request/reply sizes, and fields are validated. [Inference] Private directory ownership and modes reduce other-user access on supported Unix systems; a compromised account is out of scope. |
| Unsafe temporary files or symlink replacement | Runtime/cache paths must be private directories and reject a symlink final path. Cache publication uses a private temporary file plus atomic rename. Exact fingerprints use a secure private directory and `0600` alternate index copy, so Git's cache-tree write never touches the real index. A non-socket at the socket path is refused. Parent XDG directories remain an operating-system/XDG trust assumption. |
| Oversized diff, request, or response | Exact index copies are capped at 64 MiB. Context command output is streamed into capped buffers; source budgets are 4/12/6/6/2/2/2 KiB plus 256/128 bytes for paths/patch/symbols/manifests/subjects/path history/convention/branch/issue, with 12 KiB aggregate for Ollama and 32 KiB deterministic preview. Candidate count is three, messages 160 bytes, buffers 4096 bytes, IPC requests 16 KiB, IPC replies/cache records 64 KiB, and persistent candidate storage has validated record/byte/age limits. |
| Rapid index-change denial of service | Active repository and generation-concurrency limits bound work; jobs for a superseded scope are cancelled. A large index is rejected at the prototype limit. Rapid changes can still cause repeated snapshots and unreferenced Git tree objects, so this is mitigated rather than eliminated. |

There is no telemetry, cloud provider, automatic staging, automatic commit,
hook execution, or use of repository-supplied executable code. Ollama is an
optional loopback-only local provider; no model is pulled automatically. The
plugin's ZLE path never calculates a diff, compiles context, or runs generation;
the daemon owns bounded context collection and generation.
